## ❌ 报错怎么办（**这部分建议背下来**）

### 错误 1：`FileNotFoundError: ...\Temp\ort.quant.xxxx\model-inferred.onnx`
```
原因：你的 Windows 用户名含中文，%TEMP% 路径带中文，
      onnxruntime 量化时内部用系统临时目录，路径编码出错
解法：在导入 onnxruntime 之前，把 TEMP 指向纯 ASCII 路径
```
脚本里已经修好了，对应代码：
```python
_ASCII_TMP = r"D:\ort_tmp"
os.makedirs(_ASCII_TMP, exist_ok=True)
os.environ["TMP"] = _ASCII_TMP      # ← 必须在 import onnxruntime 之前
os.environ["TEMP"] = _ASCII_TMP
tempfile.tempdir = _ASCII_TMP
```

### 错误 2：`RuntimeError: ...axes_input_to_attribute...Assertion node->hasAttribute(kaxes) failed`
```
原因：opset 17 导出后，onnxruntime 量化时触发 ONNX 版本转换 bug
解法：导出时改用 opset 21，跳过版本转换
```
```python
torch.onnx.export(..., opset_version=21, ...)   # ← 用高版本
```

### 错误 3：`ValidationError: Data of TensorProto ... should be stored in model.onnx.data, but it is not regular file`
```
原因：torch 默认把权存成独立的 .onnx.data 外部文件，量化工具读不了
解法：导出时指定 external_data=False 输出单文件
```
```python
torch.onnx.export(..., external_data=False)
```

### 错误 4：`InferenceError: Inferred shape and existing shape differ in dimension 0: (48) vs (4)`
```
原因：ONNX 图里已有的 value_info 和形状推断结果冲突
解法：加载模型后清掉中间层 value_info 再量化
```
```python
_m = onnx.load(tmp_in)
del _m.graph.value_info[:]     # ← 清掉中间层 shape 信息
onnx.save(_m, tmp_in)
```

# 🧪 第 4 步：自己写一个推理脚本（**最重要的练习**）

## 做什么

**不看原脚本**，自己用 ONNX 模型跑一次推理。这一步能让你真正理解"部署后的模型怎么用"。

## 新建文件

在 `04_edge_deploy` 目录下新建 `my_inference.py`：

```powershell
cd "C:\Users\伍浩然\OneDrive\Desktop\ForInterview\SkillsetLab\github_repo\audio-aigc-lab\04_edge_deploy"
notepad my_inference.py
```

## 写这些代码

```python
# -*- coding: utf-8 -*-
"""自己写的推理脚本：用 ONNX 模型跑一次预测。"""
import sys
sys.stdout.reconfigure(encoding="utf-8", errors="replace")

import numpy as np
import onnxruntime as ort

# ① 创建推理会话（加载模型）
sess = ort.InferenceSession("outputs/model_fp32.onnx",
                            providers=["CPUExecutionProvider"])

# ② 看模型的输入输出规格
print("输入:")
for i in sess.get_inputs():
    print(f"  name={i.name}  shape={i.shape}  type={i.type}")
print("输出:")
for o in sess.get_outputs():
    print(f"  name={o.name}  shape={o.shape}  type={o.type}")

# ③ 造一个假输入（形状必须和模型要求一致）
x = np.random.randn(2, 1, 64, 128).astype(np.float32)

# ④ 推理
logits = sess.run(None, {"mel": x})[0]
print(f"\n输入形状: {x.shape}")
print(f"输出形状: {logits.shape}")
print(f"输出内容:\n{logits}")

# ⑤ 转成类别
pred = logits.argmax(axis=1)
print(f"\n预测类别: {pred}")
```

## 运行

```powershell
python my_inference.py
```

## 预期输出

```
输入:
  name=mel  shape=['batch', 1, 64, 128]  type=tensor(float)
输出:
  name=logits  shape=['batch', 4]  type=tensor(float)

输入形状: (2, 1, 64, 128)
输出形状: (2, 4)
输出内容:
[[ 0.123 -0.456  0.789 -0.234]
 [-0.111  0.222 -0.333  0.444]]

预测类别: [2 3]
```

## 你要理解的

| 观察到什么 | 含义 |
|---|---|
| `shape=['batch', 1, 64, 128]` | 第一维是**动态的**（`dynamic_axes` 设的），可以喂任意 batch |
| `sess.run(None, {"mel": x})` | `None` 表示"取所有输出"；`{"mel": x}` 用**名字**传输入 |
| 输出是 4 个 logits | **没经过 softmax**，要自己加 |

## 🔧 加一个 softmax，让它变成概率

在 `my_inference.py` 末尾追加：

```python
# ⑥ logits 转概率
exp = np.exp(logits - logits.max(axis=1, keepdims=True))   # 减去最大值防溢出
prob = exp / exp.sum(axis=1, keepdims=True)
print(f"\n概率:\n{prob}")
print(f"概率和: {prob.sum(axis=1)}")     # 应该都是 1.0
```

> 🔑 **为什么减最大值？** 防止 `exp(大数)` 溢出。
> 这是 softmax 数值稳定性的**标准写法**。

# 📊 第 5 步：亲手验证"为什么 int8 更慢"

## 做什么

我们**直接量化算一下**：int8 到底省下多少内存？值不值得？

## 命令

```powershell
python -c "
n = 19060
print('参数量:', n)
print()
print('fp32 权重:', n*4, 'bytes =', round(n*4/1024, 1), 'KB')
print('int8 权重:', n*1, 'bytes =', round(n*1/1024, 1), 'KB')
print('节省:', round(n*3/1024, 1), 'KB')
print()
print('换算成 MB:', round(n*3/1024/1024, 4), 'MB')
print()
print('如果设备有 8 GB 内存，省下的占比:')
print('  ', round(n*3/1024/1024/8192*100, 7), '%')
"
```

## 预期输出

```
参数量: 19060

fp32 权重: 76240 bytes = 74.5 KB
int8 权重: 19060 bytes = 18.6 KB
节省: 55.8 KB

换算成 MB: 0.0552 MB

如果设备有 8 GB 内存，省下的占比:
   0.00067 %
```

## ⭐ 这一步的意义

> **你亲手算出了"省下 0.00067%"** ——
>
> 现在把这句话说出来：
> **"int8 只省了 55.8 KB，在 8 GB 内存的设备上占 0.00067%，
> 但每次推理都要多一步反量化 —— 省的不值得，所以更慢。"**
>
> **这就是要讲的机理**，而且是你自己算出来的。
